# Limitaur first working version specification

Status: approved product scope; detailed design awaiting independent verification and role gate.

## Goal and settled constraints
Build a native macOS menu-bar app monitoring configured AI subscriptions on the machine. Operator approved initialization and the first working version on 2026-10-18. Codex and Claude only initially; Cursor deferred, provider extension supported. Swift/AppKit, no third-party runtime dependencies. macOS 26 minimum (earliest released macOS numerically >= operator's requested 20; Apple skipped 16 through 25). Three compact clockwise ring gauges start at twelve o'clock; dark neutral tracks; normal filled arcs match macOS menu-bar foreground/system appearance (not a fixed gray); yellow strictly >80 percent, red strictly >95 percent. No prediction. Dropdown shows provider/account grouped metric lines using the same thresholds, reset timing, balances, available earned resets and their expirations when provided. Read-only monitoring: no purchases, reset redemptions, model inference, telemetry, credential refresh or changes to another app's login state. Local commits; no push.

## Assumptions and implementation choices
One default logged-in account per provider auto-detected; additional explicitly configured account profiles may name a credential-source path and label. Never crawl arbitrary account files, browser profiles, transcripts or cookies. No obligation to discover accounts which the installed provider does not expose. Preferences expose provider toggles, credential-source paths, and refresh. Existing local authenticated sessions are acceptable, confirmed by operator. New third-party OAuth client registration is unavailable; use direct HTTPS usage requests with credentials read from configured local provider credential sources. Describe this honestly as local-session authentication, not independent provider OAuth sign-in. V1 does not register a new OAuth application. No third-party executable plugin loading; compile-time Swift provider registration.

## Interfaces and data model
Expose a Foundation-only LimitaurCore library and AppKit Limitaur executable. Value types Sendable: ProviderID; AccountID; UsageSnapshot(providerID, accountID, accountLabel, fetchedAt, metrics, balances, resetCredits, capabilities); UsageMetric(id, label, usedPercent optional, resetsAt optional, windowDuration optional, scopeLabel optional); CreditBalance(label, remaining Decimal optional, currency optional, expiresAt optional, unlimited Bool, known-state enum); ResetCreditSummary(availableCount optional, applicableCount optional, details optional); ResetCredit(id, label, expiresAt optional). Credential bytes never enter snapshots or CustomStringConvertible. Represent unavailable, absent/inapplicable, zero and unlimited distinctly; count-only reset summary is not an empty detail list. Adapters may add fields needed by verified schemas. Provider protocol lists identity and asynchronously fetches a snapshot using injected credential and HTTP abstractions. Provider registry owns adapter list; UI consumes normalized data only. Fetch results distinguish unauthenticated, unavailable, throttled(retryAt), transport/parse failure, success. Inject both monotonic/elapsed clock and wall-clock date sources, plus transport/credential store, for deterministic tests.

Percent validation accepts finite nonnegative usage, including >100; ring fill clamps to 100 but row preserves actual percent. Missing/null/invalid/negative/nonfinite values are unknown, never 0. Percentage classification uses raw value: <=80 normal, (80,95] warning, >95 critical. Currency amounts use Decimal and provider-supplied units/exponent; do not infer dollar values or expiration dates.

Ranking function takes snapshots, current time and health; choose up to three fresh valid unique metrics, ordered by usedPercent descending then stable providerID/accountID/metricID lexical tie-break. Multiple metrics from one provider allowed. Metric identity includes provider, account, bucket and window/scope. Exclude unknown metrics, stale snapshots older than 90 seconds, and metrics whose known reset time has passed until a new fetch confirms usage; retain them as stale in dropdown. Do not optimistically reset usage to zero. Stable provider health marker/tooltip must report unavailable or stale configured providers even if other providers fill all three rings. Empty dial slots visibly unavailable, not 0 percent. Do not rank currencies, unlimited balances, or expiring resets as quota percentages.

## HTTP and credential boundary
Native URLSession ephemeral session; fixed HTTPS origins and paths only: https://chatgpt.com/backend-api/wham/usage and https://api.anthropic.com/api/oauth/usage. These are observed internal endpoints, not promised stable public APIs. Strictly reject all redirects on authenticated requests. Disable cookies, persistent caching and credential storage; 15-second request/resource deadline; response size bounded to 1 MiB while streaming (Content-Length alone insufficient). No automatic HTTP retries; scheduler controls them. Only explicitly allowlisted request headers (Authorization, provider account header, Accept, User-Agent, anthropic-beta). Credential values never appear in URLs, argv, logs, error descriptions or persisted snapshots. Authentication files must be read only from configured/default absolute paths. Open with O_RDONLY|O_NONBLOCK|O_NOFOLLOW|O_CLOEXEC; reject a symlink at the final component (parent-directory symlinks are allowed within the operator-trusted source path). fstat the opened descriptor, require a regular file and size <=1 MiB, then bounded-read the same descriptor with a 1 MiB+1 limit; do not validate one path and reopen another. Reject oversized, unreadable, malformed and substituted-file cases without including contents in errors. Credential source is a per-profile enum: codexFile(path), claudeFile(path), or claudeDefaultDiscovery. An explicitly selected Claude file bypasses Keychain entirely. Only claudeDefaultDiscovery uses bounded Security.framework Keychain lookup for service Claude Code-credentials with authentication UI disabled; fallback ~/.claude/.credentials.json only on item-not-found, not denied/locked/malformed keychain data. Profile IDs are stable independently of mutable display labels. Where provider account IDs are returned, bind results to those IDs and reject mismatches to a configured expected ID. For Claude responses lacking account identity, bind the profile to the selected credential source plus an in-memory SHA256 access-token fingerprint; do not assert verified provider account identity. Profiles resolving to identical provider/account IDs or identical source/token fingerprints share one fetch state and one set of metrics; expose aliases rather than duplicate rings. Test two distinct profiles and duplicate aliases. Never persist or display the credential fingerprint. Keychain access failure remains visible; do not prompt repeatedly. Files and Keychain are read-only. Codex default ~/.codex/auth.json, honoring explicit configured source, reads tokens.access_token and tokens.account_id, accepts only ChatGPT-token auth; API-key-only is unsupported for subscription limits. Claude credential contract observed 2026-10-18 in both supported file and Keychain JSON: root claudeAiOauth object; accessToken nonempty string; expiresAt optional nonnegative finite integer Unix epoch milliseconds (not seconds), divided once by 1000 for Date. The active Keychain timestamp converted to a near-current future UTC date and its token returned HTTP200; the stale file timestamp converted to a near-current past date and returned HTTP401; interpreting either as Unix seconds yielded an implausible far-future date. Reject Boolean/string/nonfinite/negative/overflow expiry as malformed, never guess units from magnitude. Missing/null expiry is unknown and HTTP401/403 remains the authentication fallback. Known expiresAt <= now returns reconnect-required rather than calling or refreshing. Codex tokens.access_token and tokens.account_id are nonempty strings; auth_mode ChatGPT token mode or valid tokens object is required, OPENAI_API_KEY without that object cannot supply subscription quotas; no local expiry field is assumed for Codex. No reading refresh tokens beyond ignoring decoded fields. No token copies into app-owned storage. Preferences store source paths/labels, no token strings.

## Codex decoder
Observed direct endpoint provides rate_limit with primary_window/secondary_window; used_percent, limit_window_seconds, reset_at Unix seconds; code_review_rate_limit; additional_rate_limits; model_usage (availability flags, not percentages); credits(has_credits, unlimited, balance); rate_limit_reset_credits(available_count, applicable_available_count, details if present). Use source labels/IDs when present, otherwise neutral labels based on bucket/window, never hard-code subscription tiers or infer Astra quota from plan. Normalize optional windows; use duration to label 5h/weekly etc, not primary=5h. Prefer rateLimitsByLimitId when parsing documented app-server shape; do not duplicate legacy rateLimits when modern map exists. Direct endpoint and app-server fixtures may be supported, but no unnecessary CLI helper process in default polling. Handle empty/null additional limits without synthesizing data. Preserve model availability information as informational rows. Credits balance is provider credits unless source explicitly supplies currency; never dollar-label opaque credit units. Earned-reset available count authoritative even when details capped; show unknown expiration when not supplied.

## Claude decoder
Observed GET /api/oauth/usage, Authorization bearer and anthropic-beta oauth-2025-04-20. Prefer modern limits array when present; each row kind, group, percent, resets_at ISO8601 (fractional/offset accepted), scope.model.id/display_name, scope.surface, is_active. is_active false does not mean absent/inapplicable: observed weekly/Fable meters are false while valid. Use scope display_name Fable when supplied. Do not map opaque legacy names to Fable by guess. Distinguish same-kind scopes with stable identity and deduplicate exact duplicates without dropping distinct ones. Null limits permits legacy fallback; an empty modern list is authoritative empty. Fallback five_hour and seven_day and other recognized scoped utilization objects only when modern list absent; never double-count modern plus legacy. spend contains enabled, used, limit, balance, percent, cap (amount_minor, currency, exponent); extra_usage contains is_enabled, monthly_limit, used_credits, utilization, currency, decimal_places, and period limits. Prefer modern spend over legacy extra_usage to prevent duplication. Normalize known budgets only when enabled and measurable; respect units and missing currency. Unknown legacy objects must not create speculative Fable labels; preserve explicitly labelled modern future meters through schema-tolerant parsing. No computed transcript token estimates.

## Response validity and partial-data contract
Accept Codex direct envelopes only when at least one recognized top-level rate_limit, additional_rate_limits, credits, model_usage or rate_limit_reset_credits key exists with a valid expected container type (nullable only where the contract permits). Accept Claude direct envelopes only when limits is an array, or limits is absent/null and at least one recognized legacy utilization/spend/extra_usage container is present with valid type. Empty modern Claude limits array is authoritative only for quota metrics, not for independent spend/balances. Recognized explicitly empty/null values may represent no applicable metrics, but {} and unrecognized envelopes are schema failures. Wrong-type authoritative containers are schema failures; never fall back around malformed modern containers. Mixed valid and malformed rows produce a partial snapshot with valid rows plus an explicit incomplete-data warning; all-malformed nonempty arrays fail. Unknown future top-level fields are ignored, but do not legitimize an otherwise unrecognized response. Preserve previous snapshots on schema failure, with degraded health and normal time-based stale transitions. Partial status remains visible when three other gauges are populated. Cap accepted rows/details to 128 per profile; reject/truncate with incomplete-data warning, never silent loss.

## Scheduling, state and efficiency
One scheduler maintains shared fetch entities separately from per-profile subscriptions. A shared entity owns its canonical provider/account-or-credential identity, request epoch, one in-flight task, quota cache, transport/schema health and throttle deadline; each credential binding owns its authentication health/pause independently; enabled profile bindings hold profile ID, source identity and their own generation. Initial grouping uses provider + in-memory token fingerprint + effective account selector (Codex tokens.account_id; explicit neutral context for Claude). The selected account context is distinct from server-verified account identity. Validate configured expected account IDs against the Codex selected account before attaching a profile; reject mismatches without a request. Same Codex token with distinct account selectors remains separate request/cache contexts even when response identity is absent. Test this explicitly; when verified provider account IDs become available, entities for that account merge atomically, retaining the latest applicable cache and the maximum of all throttle deadlines. Do not assert cross-token Claude account equality without provider evidence. Every request captures its entity key and request epoch, never an alias profile's mutable label. Accept completions only for the current entity/epoch; publish them only to still-enabled current-generation subscribers whose identity binding matches. An old result/error cannot update a detached profile or another account. Changing/disabling an alias detaches only that subscription and clears that profile's displayed old usage; do not cancel or invalidate shared work while another eligible subscriber remains. Cancel shared work when its last subscriber detaches, on sleep, or on quit; increment epoch so late completion is discarded. Preserve account-level throttle state until its deadline even when all aliases detach, so re-enable/source changes cannot bypass it. A genuinely new account/source starts with independent state. Token rotation invalidates usage for the affected source binding until account identity is reestablished; it does not discard state for unaffected subscribers. Never share auth failure across distinct credentials. Credential-specific auth pause may clear on validated changed credentials or explicit reconnect; throttle deadlines still apply. For a merged verified account with multiple credential bindings, choose an eligible non-paused binding deterministically by stable source/binding ID, not mutable profile label. On a credential-specific 401/403, pause only that binding, reject late results from its invalidated epoch, and let the scheduler try at most one already-bound eligible alternate credential per nominal refresh cycle, respecting the shared throttle deadline and single-flight guard. No unbounded retries or simultaneous failover. Detaching a failed source leaves unaffected subscribers eligible. Distinguish per-binding auth status from shared account usage status in UI. Test revoked/valid credential aliases, source detachment and late failures. Deterministic tests cover late results/errors after switches and disabling, changing or re-enabling one alias while another remains subscribed, including in-flight work and preserved throttling. No overlapping tasks for a shared entity. Nominal 45-second UI cadence while awake (30 seconds until 2026-10-22; the scheduler keeps a 30-second per-entity minimum); schedule bounded jitter, coalesce wakes, timer tolerance. Credential lookup and networking off main UI thread; main-thread drawing only. Refresh on launch, wake, provider enabling and dropdown open if last successful fetch older than 10 seconds, respecting in-flight and all backoff deadlines. Manual refresh also respects Retry-After and backoff. Handle HTTP 429 with Retry-After delta/date and exponential failure backoff (30,60,120... max 15 minutes); never convert positive Retry-After to an earlier deadline through capping. Missing/invalid Retry-After uses exponential policy. Use monotonic elapsed time for request deadlines, relative Retry-After and exponential backoff; wall-clock changes cannot shorten those intervals. At receipt, convert an absolute Retry-After date into a monotonic not-before interval using the receipt wall/monotonic pair, retaining its absolute date for display; later clock adjustments cannot shorten that established minimum. Provider reset timestamps remain absolute wall-clock dates. On system clock-change notification and wake, recompute pending absolute reset/display transitions, process due transitions, and arm only strictly future ones without clearing monotonic throttles. Inject independent clocks and test forward/backward wall jumps with unchanged monotonic time, plus monotonic advancement with unchanged wall date. 401/403 auth stops periodic calls until explicit reconnect/source change or externally changed credential fingerprint; show actionable account state. Auth fingerprint must not expose token contents and avoid busy polling. Other providers continue independently after one fails. Sleep cancels outstanding work; wake does not bypass throttling. No per-second timer with dropdown closed; reset labels may update once per minute while open. Cache last snapshots in memory only, bounded to accounts and limited metric/detail counts. Observe local file changes if practical without directory scans; otherwise explicit refresh/source action clears auth pause. Independently of network deadlines, schedule a coalesced one-shot display invalidation at the earliest monotonic freshness deadline or known provider absolute reset deadline converted using the current wall/monotonic pair. Reevaluate ranking/health at that deadline and on wake even if network is backed off; no per-second polling. Record both fetchedAt wall date for display and successfulFetchInstant from a monotonic clock (ContinuousClock or equivalent including elapsed sleep). Snapshot freshness requires monotonicNow < successfulFetchInstant+90 seconds and, for a known reset, wallNow < resetsAt. At exact equality the transition is due: exclude the stale/expired metric. Process all transitions due at now, then arm only the earliest strictly future deadline; already-expired retained snapshots/windows must never reschedule an immediate timer. Test exact equality at age 90 seconds/reset time and repeated reevaluation under long backoff without busy loops. A fetch failure immediately marks account health degraded, exposes the failure marker, and retains previously fresh usage until its time boundary; after that boundary the old usage remains in dropdown as stale and is excluded from ranking. Redraw rings only if display changes; no continuous animation/spinner or persistent child process. No permanent login helper, login-item enabling, install or external service changes in this task.

## Non-goals / open limitations
No own OAuth client registration, browser-cookie harvesting, inference-based probing, balance transactions, reset redemption, alerts/notifications/history/burn-rate forecasts, automatic launch-at-login, notarization/App Store/release publication or remote repository. Account credentials must already exist from supported provider sessions. Multi-profile configuration does not discover inaccessible accounts. Credit expirations or earned-reset metadata absent from a provider remain unknown. New upstream auth/endpoint incompatibility must produce visible unavailable state and preserve last known data as stale.
