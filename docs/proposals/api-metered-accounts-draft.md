## Metered accounts
- Provider identity and metering mode are separate. Preserve existing Codex/Claude subscription sources; add explicit reporting-file sources for OpenAI API and Claude API, never reinterpret a subscription token or inference key as reporting access. Native Settings selects a pre-existing credential JSON file (api_key string), budget/currency, billing scope and UTC monthly period. Persist path/configuration only. Read through SecureFileReader with the same bounds, no symlinks/FIFO, read-only; do not create/copy credentials. No arbitrary scanning, auth refresh or Keychain writes. Missing reporting source remains configuration-required.
- Immutable reporting context includes provider, reporting versus subscription mode, credential binding, organization context, exact project/workspace/filter set, declared report coverage and configuration generation. Different scopes never merge even with the same verified organization. Credential type and endpoint/header policy belong to this context.
- Reporting organization identity is unverified unless the supported provider request selector/response proves it. User display labels are not proof. When no documented identity-verification method is established, expose a credential-bound reporting context with "organization unverified" and bind the user budget to that exact credential fingerprint and scope; no claim of named-organization enforcement. Credential replacement invalidates this budget binding until the user explicitly reestablishes it or provider identity is independently verified. For organization-unverified scopes, each process restart also requires explicit user reestablishment before ranking; persisted paths/budgets never auto-bind to newly loaded credentials. Unchanged and replaced credentials across restart both remain informational until that action. Automatic restoration is permitted only after independently verified identity and exact scope continuity. Test both restart cases.
- Add typed spend budget (Decimal spent/cap, currency, period start/end, scope identity, cap origin configured versus verified provider-enforced). Known complete spending and positive finite cap in matching units/scope gives spent/cap*100 and ranks with quota percentages. Unknown/mismatched cap or currency is no gauge; zero spent is known zero only after valid complete report. No credit balances derived from spent. Values above cap keep raw percent and clamp only drawing. Configured caps are clearly labelled user budgets, never hard provider limits.
- Implement reporting adapters using fixed GET hosts/paths and URLComponents query encoding: OpenAI https://api.openai.com/v1/organization/costs with Bearer reporting credential; Claude https://api.anthropic.com/v1/organizations/cost_report with x-api-key and anthropic-version. Current official contracts below. Share transport redirect rejection/streaming body bounds/cancellation/deadline; never send billing credential to subscription endpoints or redirects. No custom URLs/headers in settings. Credentials excluded from descriptions/errors.
- Query current UTC calendar month [start, current instant), automatic month rollover. Scope organization (full report) or explicit project for OpenAI/workspace for Claude; cap applies to exact selected scope. Configure scope labels explicitly; never equate different organizations from the same provider. Do not claim per-user support from org/project totals. Separate reporting credentials/sources form separate entities unless the provider proves identity. Cache only normalized period totals in memory.
- Fetch all pages within a bounded cycle (max4 pages, max4096 rows and existing1MiB per response); repeated/missing/oversized cursors, out-of-month/overlapping buckets, malformed amounts or scope mismatch invalidate completeness and prevent budget percentage. Canonical daily buckets may enclose the captured query cutoff (bucket end is not an as-of time). Provider current-day clipping semantics are not established by the supplied docs. Preserve raw reported monetary totals without prorating/clipping; label them reported subtotals with source-update time unknown. Until provider-specific query-cutoff/coverage semantics are verified and documented, current-day ambiguous totals remain informational without a budget gauge. Never reject a report only because a canonical daily bucket end is after cutoff, and never infer complete current-instant spending from it. Month boundaries and whole-period applicability remain strict; add current-day and rollover fixtures. No partial total presented as complete. Bound total cycle deadline; cancellation and any page401/403/429 retain standard pause/throttle semantics. Use decimal parsing and reject nonfinite, negative, exponent/range overflow and currency mismatch. Pagination completeness is separate from source coverage. Empty complete valid reports mean known0 only for the declared supported coverage. Claude Priority tier costs are omitted: overall budget remains informational/unranked unless coverage is explicitly limited to reported categories and labelled that way. Never present a supported-category subtotal as total organization spending. Document omissions next to amounts. Each cycle captures immutable period/start/cutoff, scope, currency, coverage and config generation across all pages. Config/period changes invalidate pending cycles and prior applicability. Remove prior-month totals from ranking at exact UTC rollover even under backoff or fetch failure; schedule that boundary independently.
- Poll billing no more often than60s, including manual/dropdown actions, retain provider Retry-After/backoff. Subscription nominal30s unchanged. Freshness remains90s from successful fetch; show source lag/unknown source-update time independently of fetch time. Official Claude cost reporting typically lags5min or longer; polling does not imply realtime costs. Do not fabricate a report as-of timestamp from future bucket end.

## SemVer and release tooling
- VERSION0.1.0 is the only authored app version. Strict SemVer2 grammar including prerelease/build metadata, one terminal newline allowed; leading-zero core/numeric prerelease, empty components/whitespace invalid. CHANGELOG.md includes Unreleased and matching version. Before1.0 breaking changes bump minor; fixes patch; feature changes minor. Compatibility surface: adapter interfaces, persisted config and documented diagnostics.
- Build script generates bundle short version numeric core and separate full SemVer key; --version/About agree with VERSION via generated metadata/source input. CFBundleVersion uses explicit validated positive numeric build number or full-history Git count in supported Apple format; record full source revision; reject shallow history without explicit number. Do not make release checks create commits/tags/pushes.
- scripts/release-check.py has explicit prepare and verify phases. Prepare builds into explicit ignored output, runs release build/Swift/frozen tests and checks plist, LSUIElement, macOS26 minimum, executable/signature and hashes, then generates a new random freeze UUID and freezes a manifest with commit/tree, validated build inputs, artifact tree digest and executable digest. Collect all live/UI/resource/review evidence against that unchanged frozen candidate, freeze UUID and manifest digest. Every new prepare has a new UUID even if bytes match and therefore needs renewed evidence. Verify reads candidate/source/evidence without rebuilding or replacing the candidate; freeze UUID/manifest digest or source/input/artifact mismatch blocks and requires new artifact-bound evidence. No reproducible-binary claim. Source remains unchanged. Strict clean worktree including nonignored untracked paths, changelog/version/tag equality (when proposed tag provided), bundle/executable version agreement. --development can report partial checks but never release-ready.
- Qualifying release requires separately supplied sanitized evidence directory bound to exact current Git commit/tree and frozen artifact SHA256: independent reviewer/panel acceptance with no unresolved required fixes; actual app-bundle Codex+Claude integration; light/dark anchored UI/keyboard/scrolling/accessibility; and original A7 live workload resource evidence (60s warmup,600s measured,18 successful refreshes/provider, no pauses/throttles/helpers, max RSS<50MiB, one-core meanCPU<0.1%). Missing or unverified is blocked, never implicit pass. API live readiness explicitly separate from core subscription release and labelled unverified until configured/reporting tested; do not advertise live API qualification from fixtures.
- Evidence parser is data only; validate exact schema/types, finite nonnegative numbers, all success/count/duration/hash conditions, bounded report sizes, no symlink/path traversal outside selected directory, secret pattern rejection without echoing content. No commands from evidence, no credentials read, no tag/release/publish actions. Reports outside tree avoid self-reference. Ad-hoc signature integrity is not notarization/distribution signing.
