## Goal

On 2026-10-23 the live M1 gate failed: Claude Code refreshed its OAuth token at 00:47:06Z by rewriting the Keychain item `Claude Code-credentials` through `/usr/bin/security add-generic-password -U`, and from that instant Limitaur's own `SecItemCopyMatching` read of the item was denied, although the operator had granted Always Allow to this signed build the same day; the rewrite had removed the app's standing access to the item. So every token refresh can revoke Limitaur's access and the automatic resume designed in `credential-recheck.md` cannot be relied on for the Keychain source. The same session showed two related costs: polls of the superseded token answered 429 within a minute of the rewrite, and a machine where nobody runs the `claude` command lets the token expire within hours and stays dark until someone does. Solving the problem means: (A) Limitaur reads the Claude Keychain item the way its writer does, through a child `/usr/bin/security` process, so a token refresh does not revoke access; a background read that does not return within five seconds, or that a person answered with Deny, is abandoned and that source is not read again in the background until Connect / Authorize completes or the app relaunches, so at most one dialog per source per launch can appear without user action; after a 401, 403 or 429 the credential is re-read at the next tick so a rotated token is bound within one poll, one tick and the 30 s load cooldown of that failure instead of five minutes; (B) the poll interval per provider adapts to the provider's 429 responses within operator-set bounds (30 s to 120 s, +10 s or the Retry-After on a 429 that the immediate re-read does not attribute to a superseded token, −10 s only after 24 h and five consecutive clean polls, a reduction reverted and that level blocked for seven days if a 429 follows within an hour) and never hunts; (C) with an opt-in setting, when a non-interactive re-read of the default Claude Keychain item returns an expired token, Limitaur runs one minimal `claude -p hi --model haiku` so that Claude Code itself refreshes the token, at most once per hour per source while it stays expired, then re-reads. Everything else — read-only credentials, no token refresh by Limitaur, the freshness and Retry-After rules for providers without an active policy, the existing floor semantics per driver, the bar semantics — stays as it is.

## Assumptions (designer)

- A-1 `/usr/bin/security find-generic-password -a <user> -s <service> -w` on an item last saved by `security` for that account does not prompt; the pattern is used by openusage (`Sources/OpenUsage/Services/SecurityToolItemAccessor.swift` and `SystemClients.swift`, verified by a reviewer at the repository's main branch on 2026-10-24) and mac-ai-trackers (`AIUsagesTrackers/Sources/AIUsagesTrackers/Connectors/ClaudeTUICredentialLocator.swift`, read by the designer from a clone on 2026-10-23), and by Claude Code's own prompt-free reads; conditional on the item's actual access list and on Claude Code writing with `-a <user>` and without `-T`. Qualified on this machine by the probe (A10, scratch items) and proven for the real item only by the live gate L1.
- A-2 `security` exits with the low byte of the failing OSStatus; only exit 44 (observed for a missing item) changes behaviour; every other non-zero exit, a signal, a timeout or oversize is treated as denied. Residual: Apple's tool also reports some search failures as item-not-found, so a search failure could trigger the fallback-file read; the probe's not-found step qualifies the ordinary case only.
- A-3 False, verified by the operator's probe run on 2026-10-24: killing the child's process group ends the read but leaves the SecurityAgent dialog on screen until answered. The design does not rely on it; the per-launch suspension rule bounds exposure to one dialog per source per launch.
- A-4 A 429 answered to a token that the immediate re-read shows to have been superseded is treated as the stale-token cascade rather than a rate signal (mac-ai-trackers, `docs/vendors/claude-tui.md`, "Stale-token failure mode", read by the designer from the clone). Consequence stated precisely: the provider's Retry-After and the local backoff are enforced regardless; only the learning signal is discarded, each time such a coincidence occurs. Without this rule, routine token rotations would ratchet the interval to the ceiling faster than the daily probe can lower it.
- A-5 `claude -p` in a non-TTY process with an expired access token refreshes it through the stored refresh token and rewrites the Keychain item before answering. Unverified by review; L3 qualifies it on each machine where the setting is enabled. The behaviour with a dead refresh token (exit without a browser) is unverified and stays so until observed; the 60 s timeout bounds the process either way.
- A-6 `security -w` prints the item data raw when every byte is printable in the C locale and as lowercase hexadecimal otherwise, followed by a newline (Apple's SecurityTool `keychain_find.c`, cited by a reviewer). Claude Code writes compact single-line ASCII JSON; the reader handles both forms; the probe qualifies both.

## Part A: Keychain read through `security`, reactive re-read

### A1 Process runner (ProcessRunner.swift)

```swift
public enum OutputMode: Sendable, Equatable { case capture(limit: Int), discard }
public struct ProcessResult: Sendable, Equatable, CustomStringConvertible {
    public let exitCode: Int32?      // nil: not launched, killed by a signal, or shutting down
    public let signaled: Bool
    public let output: Data          // empty for .discard
    public let timedOut: Bool
    public let oversized: Bool
    public var description: String   // never includes the output
}
public protocol ProcessRunning: Sendable {
    func run(executable: String, arguments: [String], environment: [String: String], workingDirectory: String?,
             timeout: TimeInterval, graceAfterTerm: TimeInterval, output: OutputMode, registry: ProcessRegistry?) -> ProcessResult
}
public final class ProcessRegistry: Sendable { public static let shared: ProcessRegistry; public init(); public func terminateAll() }
public struct SystemProcessRunner: ProcessRunning { public init() {} }
```

`SystemProcessRunner` uses `posix_spawn`: `POSIX_SPAWN_SETPGROUP` (group 0), `POSIX_SPAWN_CLOEXEC_DEFAULT`, `POSIX_SPAWN_SETSIGDEF` for all catchable signals and an empty signal mask; stdin and stderr from and to `/dev/null`; stdout to `/dev/null` for `.discard` or to a pipe for `.capture`; the environment exactly as given; `chdir` to `workingDirectory` when given. `executable` must be absolute, else `exitCode nil`. The pipe is drained on a dispatch queue into a buffer of at most `limit + 1` bytes; a byte beyond `limit` sets `oversized` and sends SIGKILL to the group. Timeout: (r7) `expire` first checks `waitid(P_PID, pid, WEXITED | WNOWAIT | WNOHANG)` and marks `timedOut` only if the leader is still running, so a child that exits normally at the deadline is not reported as timed out; (r8) EINTR on that probe is retried and any other probe error is treated as "still running" so the bound is kept (signalling remains guarded by the reaped flag); then SIGTERM to the group, SIGKILL to the group after `graceAfterTerm`, `timedOut` set; (r7) once a timed-out leader has exited, the remaining group receives SIGKILL at that moment rather than after the grace (Part C designs against this); (r6) the timeout escalation completes against the whole group whether or not the child is registered, and is not cancelled by the leader's exit while the leader is unreaped (a TERM-ignoring descendant of an unregistered child must not survive a timeout). Exit observation: `waitid(P_PID, pid, WEXITED | WNOWAIT)` first, so the zombie leader still holds the group id; then, for a `registry != nil` child, SIGKILL to the group (grandchildren of `security` are never wanted) and up to 2 s for pipe EOF; for a `registry == nil` child no group signal after a normal exit, and the pipe is closed at EOF or after 2 s; then `waitpid` reaps. (r6, r7 wording) If `waitid` fails with anything other than EINTR, or `waitpid` fails, the runner sends no further signal after detecting the failure, removes the PID from the registry and returns `exitCode nil`; the runner is the only reaper in the process and documents that prerequisite. (r6) After the output has been extracted, the shared state's buffer is cleared under its lock before returning, on every path, so a cancelled timeout work item retains no item data. A child that ended by signal reports `exitCode nil, signaled true`. The escalation work item is cancelled after reaping; no PID is signalled after reaping. A `ProcessRegistry` holds live groups under a lock with a `shuttingDown` flag; (r6) a registered spawn checks the flag, spawns and registers under that lock's protection as one admission step, so `terminateAll()` (which sets the flag and kills every registered group) cannot return while an admitted spawn is unregistered; a registered spawn after the flag is set returns `exitCode nil`. The app passes `ProcessRegistry.shared` and calls `terminateAll()` from `applicationWillTerminate`; `Monitor.init` takes `terminateChildren: (@Sendable () -> Void)? = nil`, called by `stop()`. Nothing read from a child is ever logged or placed in an error.

### A2 Reader (Credentials.swift)

```swift
public enum KeychainReadReason: Sendable, Equatable { case found, notFound, exit(Int32), timeout, signaled, oversized, launch, suspended, busy }
public struct KeychainReadOutcome: Sendable { public let result: KeychainResult; public let reason: KeychainReadReason }
public final class KeychainSuspensions: Sendable { public static let shared: KeychainSuspensions; public init(); public func isSuspended(_ service: String) -> Bool }
public struct SecurityToolKeychainReader: KeychainReading {
    public init(runner: any ProcessRunning = SystemProcessRunner(), service: String = "Claude Code-credentials",
                account: String = NSUserName(), registry: ProcessRegistry? = .shared, suspensions: KeychainSuspensions = .shared)
    public func claudeCredential() -> KeychainResult                       // = claudeCredentialDetailed(interactive: false).result
    public func claudeCredential(interactive: Bool) -> KeychainResult
    public func claudeCredentialDetailed(interactive: Bool) -> KeychainReadOutcome
}
```

Behaviour of `claudeCredentialDetailed(interactive:)`:

1. Admission: one active read per service, under the `KeychainSuspensions` instance's lock keyed by service. A non-interactive read first waits for any active read of the service to finish (r7: at most 8.5 s, the 5 s timeout plus 1 s grace plus the 2 s drain bound), then, still under the lock, returns `.denied/.suspended` without spawning if the service is suspended, or `.denied/.busy` without spawning if an interactive read is active or pending, or (r8) if a non-interactive read is still active when the 8.5 s wait expires (busy spawns nothing and is retried; it is never reported as a denial). (r6) `.busy` is not a denial: `loadDetailed` reports it as `busy == true` and the monitor treats such a load like one still in flight (no message, no counter, no pause). An interactive read waits for an active non-interactive read, marks the service `interactiveActive`, and runs. Suspension is in-memory, per `KeychainSuspensions` instance (the shared one per launch).
2. Run `/usr/bin/security` with `["find-generic-password", "-a", account, "-s", service, "-w"]`, environment `[:]`, no working directory, timeout 5 s and `graceAfterTerm` 1 s when `interactive == false`; 600 s and 5 s when true; `.capture(limit: 2_097_154)` (hexadecimal transport doubles the size, plus newline); the reader's `registry`. One child per read; there is no retry without `-a` (an MCP OAuth entry or a stale item under another account must not be bound).
3. Classification, in this order (r5: `timedOut` first, because a timed-out child is ended by signal and therefore also has a nil exit code; the r4 order made every real timeout a `.signaled` and defeated suspension, as the blind test-writer predicted): `timedOut` → `.denied/.timeout`; `exitCode nil` → `.denied` with `.signaled` when the child ended by signal, else `.launch`; `oversized` → `.denied/.oversized`; exit 44 → `.notFound/.notFound`; any other non-zero exit → `.denied/.exit(code)`; exit 0: drop exactly one trailing `\n`; if the remaining bytes are all lowercase or uppercase hexadecimal digits with even length of at least two, decode them once (A-6); empty or more than 1 048 576 decoded bytes → `.denied/.oversized`; else `.found/.found`.
4. Suspension transitions, under the lock at completion: a non-interactive read ending in `.timeout`, `.exit(51)` or `.exit(128)` suspends the service; (r7) if an interactive read was admitted while it ran, the suspension is deferred instead: it is discarded when that interactive read ends in `.found` or `.notFound` and applied when it ends any other way; and (r6) that read itself reports `suspended == true` through `loadDetailed` so the wording appears at once rather than at the next refused read; an interactive read clears the service's suspension only when it ends in `.found` or `.notFound` (r6: a Connect answered Deny or Cancel, or timed out, leaves the source suspended), and always clears `interactiveActive`.

`CredentialStore` gains `public func loadDetailed(_ source: CredentialSource, now: Date, interactive: Bool = false) -> (result: Result<Credential, CredentialFailure>, viaKeychain: Bool, suspended: Bool, busy: Bool)`; `load` wraps it. `viaKeychain` is true only for a Keychain `.found`; `suspended` is true when the reason was `.suspended` or when the read itself suspended the service (r6); `busy` is true for `.busy`. `CredentialStore.init` defaults `keychain` to `SecurityToolKeychainReader()`.

### A4 Reactive re-read and provenance (Monitor.swift)

- `Monitor.init` gains `reactiveRecheck: Bool = false` (the app passes true). New actor state `recheckDue: Set<String>` and `stopped = false` (set by `stop()`). `beginLoad` uses `loadDetailed` and passes `viaKeychain` and `suspended` to `loaded()`.
- With `reactiveRecheck`, in `complete()`, in the `401, 403` branch and in the `429` branch, after the existing handling: for every subscriber whose binding's credential fingerprint equals the request's `fingerprint`, insert its id into `recheckDue`. The 429 branch also records `entity.pendingThrottle` (B2) when a policy is active.
- `recheckCredentials(driver:)`: the candidate set becomes profiles with `profile.enabled && loading[id] == nil && (isCredentialLess(profile) || recheckDue.contains(id))`. The expiry-marking block runs only for `isCredentialLess` profiles, exactly as at baseline. A `recheckDue` profile is due when `driver != .internal`, `awake`, and `now − (lastLoad[id] ?? −∞) >= 30`; when its load is issued, `recheckDue.remove(id)`. The one-read-per-source-per-pass rule is unchanged; `credentialRechecks` counts these reads too. Connect precedence (R6) is preserved by the `loading[id] == nil` guard.
- (r7) Busy retry, with `reactiveRecheck` only (r8: the whole busy branch, including the early return, is gated; a default monitor handles a busy load through the baseline denial path): a busy result for an explicit or launch load records `busyRetry[id] = clearPause`; a busy result for a re-check re-inserts the id into `recheckDue`; `recheckCredentials` re-issues each `busyRetry` load as an explicit non-interactive load with the recorded `clearPause` when the profile is enabled, not loading, awake, the driver is not `.internal`, and 30 s have passed since `lastLoad`, and (r8) a source retried this way is excluded from the same pass's cached re-check list and its `recheckDue` entry removed (the one-read-per-source-per-pass rule applies to cached re-checks; each busy retry is a per-profile explicit load, r8 note from change review 4; the explicit read satisfies the pending re-check); (r8) a newer explicit load for the profile consumes any older `busyRetry` entry at admission; entries are dropped with `recheckDue`. A busy admission spawns nothing, so the retry costs nothing until the competing interactive read finishes.
- Suspended wording (with `reactiveRecheck` only; a default monitor keeps baseline denial handling, r6): a load whose `suspended` is true sets, for a bound profile, `binding.message = suspendedMessage` ("Keychain read did not finish; answer any Keychain dialog, then choose Connect / Authorize") whatever the current message and whether or not the binding is paused (a 429 leaves it unpaused), on `.wakeRecheck` too (a suspended read spawns nothing, so the baseline reason for ignoring wake denials does not apply), and for an unbound one `profileFailures[id] = (.unauthenticated, suspendedMessage)`; it counts `eligibilityCounts["keychainSuspensions"] += 1` once per transition into that wording; Connect precedence (`loading[id]` epoch) is unchanged. `recheckMessage` treats `suspendedMessage` as a member of the denied family: a later non-denied re-read restores `pausedMessage` on a paused binding and `nil` on an unpaused one. A `busy` load changes nothing.
- Rotation counter: in `loaded()`, the path that binds a different unexpired token to a profile whose prior binding existed and was not paused (the `else` branch at baseline line 534 reached with `origin.isRecheck`) counts `credentialRotations`; `credentialResumes` keeps counting a resume of a paused binding and a bind where no binding existed, as the frozen suite pins. Entity carry on rebind is exactly the baseline (`throttleUntil`, `retryDate`, Codex verified-throttle merge); no snapshot, health or freshness is carried, so the bars for that account are empty until the first success with the new token (residual, bounded by the carried throttle).
- `recheckDue` entries are dropped with their profile (`setProfiles`, `detach`) and on `stop()`.

Latency, stated: a rotation is noticed at the first poll that fails with 401, 403 or 429 (a provider that keeps honouring the old token delays this until the old token's expiry pause, which re-reads on the baseline cadence); the re-read follows at the first cycle tick at least 30 s after the profile's last load (so within 30 s plus one tick of that failure, while awake and unsuspended); the first request with the new token follows immediately when the entity is idle and unthrottled, otherwise at the carried throttle deadline.

## Part B: learned polling interval

### B1 Policy (Polling.swift, pure)

```swift
public struct PollingPolicy: Sendable, Equatable, Codable {
    public static let floor: TimeInterval = 30, ceiling: TimeInterval = 120, step: TimeInterval = 10
    public static let probeWait: TimeInterval = 86_400, cleanRequired = 5
    public static let revertWindow: TimeInterval = 3_600, blockDuration: TimeInterval = 7 * 86_400
    public private(set) var interval: TimeInterval = 50
    public private(set) var consecutiveClean = 0              // not persisted (CodingKeys exclude it)
    public private(set) var lastChange: Date?                 // wall, persisted
    public private(set) var lastReduction: Reduction?         // struct { from, to: TimeInterval; at: Date }
    public private(set) var blockedUntil: [Int: Date] = [:]   // key: interval in whole seconds
    public init()
    public mutating func recordClean(now: Date, reductionAllowed: Bool) -> Bool   // true when the interval changed
    public mutating func recordThrottle(now: Date, retryAfter: TimeInterval?) -> Bool
    public mutating func recordOther()                        // resets the clean streak
    public static func decode(_ data: Data, now: Date) -> PollingPolicy
}
```

Rules, evaluated in the order written:

- `recordThrottle`: `r` = `retryAfter` rounded up to a multiple of `step`, 0 when nil, non-finite or negative. If `lastReduction` exists and `0 <= now − lastReduction.at < revertWindow`: `interval = min(ceiling, max(interval, lastReduction.from, r))` (r10: never below the current interval, because a receipt settled late with its original receipt time can arrive after a later increase), `blockedUntil[Int(lastReduction.to)] = now + blockDuration`, `lastReduction = nil`. Else `interval = min(ceiling, max(interval + step, r))`. Then `consecutiveClean = 0`, `lastChange = now`. Returns whether `interval` changed.
- `recordClean`: (1) remove `blockedUntil` entries `<= now`; (2) if `lastChange == nil` → `lastChange = now`; (3) if `now < lastChange` → `lastChange = now`, `consecutiveClean = 0`, return false; (4) `consecutiveClean = min(consecutiveClean + 1, cleanRequired)`; (5) return false unless `reductionAllowed`, `consecutiveClean >= cleanRequired`, `now − lastChange >= probeWait`, `interval − step >= floor`, and `blockedUntil[Int(interval − step)] == nil`; (6) `lastReduction = (from: interval, to: interval − step, at: now)`, `interval −= step`, `consecutiveClean = 0`, `lastChange = now`, return true.
- `recordOther`: `consecutiveClean = 0`.
- `decode`: structural failures return `PollingPolicy()`: malformed JSON; `interval` not a multiple of `step` in `[floor, ceiling]`; `lastReduction.from/to` not such multiples or `to != from − step`; a `blockedUntil` key not such a multiple. Date fields are clamped, never rejected: `lastChange` and `lastReduction.at` later than `now` become `now`; a `blockedUntil` date later than `now + blockDuration` becomes `now + blockDuration`; entries `<= now` are dropped. `consecutiveClean` starts at 0 after decode.
- Clock: wall time only, persisted. A forward wall jump can bring one probe or one block expiry early; a backward jump defers them. Residual.

(r11) `NudgeFileChecking` is the thin POSIX seam, and nothing else:

```swift
public protocol NudgeFileChecking: Sendable {

    func stat(_ path: String) -> stat?       // follows symlinks; nil on failure
    func lstat(_ path: String) -> stat?      // does not follow symlinks; nil on failure
```

Every acceptance, ownership, directory-creation and mode-correction decision below is made inside `ClaudeCLINudger` from these six calls, with the current user taken as `getuid()`, so a fake file system exercises the whole policy; the seam carries no policy of its own.
