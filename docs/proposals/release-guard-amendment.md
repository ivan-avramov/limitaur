# P73 guard amendment: explicit read exclusions

Status: proposed after three strict amendment-review rounds; final corrections are **NOT RE-REVIEWED**, no convergence claim, not approved for execution. Original release-tooling specification SHA256 `34f97eae0e87f62c7c50db8140ddf2f644419270643cd37641ac5f58d06a5f76` stays unchanged. This changes a real read boundary and needs approval before use. Design/review work proceeds under P216 “proceed”; no new payload/profile executes in this pass. P119 remains accepted, frozen tests unchanged, no push. See docs/reviews/release-guard-amendment.md for findings and limits.

## Recommendation and trade-off

Replace the global default-deny OS-data-read allowlist with explicit read exclusions. Keep direct network denial, scratch-only writes, immutable source/test inputs, isolated environments and all release gates. This is a cooperative local-development guard, not protection against hostile helpers or complete host-secret isolation. **Model-generated implementation/plugin/test code runs under this weaker read policy before final review**, including the independent writer's PhaseA/B payloads. It permits additional system reads outside the exclusions. A payload could copy readable host data into WORK and then into a staged/published artifact; network denial does not prevent this artifact output path. Final review/secret scanning does not prove the absence of all host data. The single approval must cover this trade-off throughout the subsequent P73 development phases, not just the baseline pilot.

Concretely, unexcluded data such as `/Library/Preferences`, `/Library/Application Support`, `/Library/Managed Preferences` and world-readable `/private/etc` files may be readable. Add the logs, core dumps and Homebrew/local service-data exclusions specified below. Unknown sensitive files elsewhere may remain readable. If that residual access is unacceptable, do not approve this amendment.

Approval would adopt v2 for development **and the eventual accepted production prepare tool**, not a temporary diagnostic exception. Each future prepare would use these exclusions and trusted-parent canaries. The separate frozen-code execution/acceptance gate remains before that tool first runs normally. Direct file/network syscall controls do not establish containment of Mach, LaunchServices/launchd-spawned processes or brokered networking/filesystem actions; those are unproven possible escape/data routes, not locally measured bypasses. Cooperative code must not request them. No complete home/credential protection against hostile code is claimed.

Unchanged v1/v2 default-allowed classes also leave process arguments/environment access, signals, POSIX shared memory and pasteboard access outside measured containment. [Public XNU source](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_sysctl.c) permits some process-environment reads depending on identity/code-signing restrictions; no matching-host probe or guarantee is asserted. Cooperative payloads must not inspect other processes' arguments/environment, signal unrelated processes, use shared memory/pasteboard or request detached/brokered work. The unchanged collector's declared resource-statistics tests remain permitted; they do not authorize credential/process-environment probing. No new process-info/signal policy is silently added. The marginal read expansion is filesystem data, not a new claim that these older routes are safe.

Payload output sent to any model is restricted to validated pre-registered test identifiers/outcomes/counts, fixed reason/error categories and locations mapped to already audited source paths; never raw subprocess output, assertion values, tracebacks, unexpected dynamic names, host paths or arbitrary snippets. Scan the sanitized report and staged brief with the existing secret-pattern rejection before dispatch. Missing/unrecognized output becomes a fixed failure, not text forwarded for debugging. This reduces a second data route through model feedback, but pattern checks do not prove absence of all encoded/sensitive information. Normal authenticated model CLIs and artifact output remain outside any claim of hostile-helper containment.

The measured strict profiles aborted during ignition/loader startup before fixed markers. One-cache-root addition was insufficient. A broader diagnostic read policy allowed markers/canary reads, but no missing resource was attributed; reporting controls failed. These observations motivate trying a different contract, not claiming this amendment works or identifies the fault. On this host `sw_vers` reports macOS27.0.1 build26A434; source-version equality is unproven.

Attribution is narrower than that shorthand: the inspected echo crash report showed the ignition/loader frames; Python startup aborts had no equivalent resource attribution. Compared with the successful broad diagnostic, **all** new exclusions, temp-data filter, SOURCE/TRUST layout, filtered STAGE writes, link denial and expanded controls below are untested changes. The complete declarative proposal is [guard-v2-template.json](release-fixtures/read-exclusions-v2/guard-v2-template.json), with full invented rendered bytes in [guard-v2-golden.json](release-fixtures/read-exclusions-v2/guard-v2-golden.json). These strings are not live profiles and have never been compiled/applied.

| Property | Earlier broad startup-only diagnostic | Proposed operative contract |
| --- | --- | --- |
| Global OS-data allowlist | removed | removed; explicit exclusions replace it |
| Private temp data | generally readable | denied except current TRUST/WORK aliases; metadata allowed |
| Home/system-secret roots | earlier fixed exclusions | expanded aliases, resolved known config homes, logs/service/core exclusions |

Alternatives: retain the original policy and leave execution blocked, or separately scope a disposable macOS guest with no host home/credential/share mounts. A guest requires its own setup, toolchain and evidence qualification; it is not installed or presumed available. Recommend the current-host amendment for this cooperative development task. If the requirement is protection of arbitrary unknown host files against hostile payloads, reject this option and choose a separately designed environment boundary.

Apple DTS [describes custom SBPL as undocumented for third-party use](https://developer.apple.com/forums/thread/661939). This remains a host-qualified private mechanism, not a supported security API or a claim of portability. Apple's [macOS guest documentation](https://developer.apple.com/documentation/virtualization/running-macos-in-a-virtual-machine-on-apple-silicon) describes a separate environment option, not an already configured one here. No SIP/bootarg/entitlement changes, tracer, new Mach allowance, copied credentials, re-signing of system tools or privilege escalation.

## Exact policy contract

Keep profile version1 for this increment; do not change language version or introduce report/debug-based qualification. Two templates, build and diagnostics, with recorded bytes/hash/metadata, held outside child-writable roots. Conceptual operations:

1. Allow default operations, deny network*, deny file-write*, deny file-link. Permit writes only to private WORK and literal `/dev/null` (the existing null-device allowance). No source, home, SDK/tool or external cache write exception. SOURCE is moved into read-only TRUST/source, outside WORK; it contains only the audited tracked export. WORK contains build/test scratch, synthetic HOME/TMPDIR and the staged-app root STAGE. Other-role copies/records must be under excluded home or private-temp prefixes; no other role receives TRUST/WORK exceptions. These placement checks apply before each payload launch. Candidate-blind model briefing remains cooperative; payload guards do not sandbox the normally authenticated model CLI itself.
2. SOURCE/TRUST have no write allowance. Build permits staging/signing under WORK. Diagnostics' WORK write filter explicitly excludes every STAGE alias, rather than combining an unrestricted WORK allow with an order-dependent STAGE deny. Express write allowance with component-aware `require-all`: WORK-alias membership AND NOT STAGE-alias membership for diagnostics; build uses WORK membership. Global file-write denial supplies the remainder. Denying file-link applies within scratch too; failure of a build that needs links stops rather than granting them. Before/after byte/mode/link-count audits remain mandatory: direct controls do not prove every mutation route impossible. Apply no package sandbox nested inside the outer profile; retain approved `--disable-sandbox` and fixed SwiftPM flags.
3. Do **not** add global deny file-read-data or reconstruct an OS/SDK read allowlist. Read file data/metadata are permitted by default except explicit rules below. No read allowance may override an unconditional sensitive-root exclusion.
4. Deny file-read* under `/Users`, `/System/Volumes/Data/Users`, `/private/var/root`, `/var/root`, `/System/Volumes/Data/private/var/root`, `/Library/Keychains`, `/System/Volumes/Data/Library/Keychains`, `/private/var/db/ConfigurationProfiles`, `/var/db/ConfigurationProfiles`, `/System/Volumes/Data/private/var/db/ConfigurationProfiles`, `/private/var/db/shadow`, `/var/db/shadow`, `/System/Volumes/Data/private/var/db/shadow`, `/private/etc/ssh`, `/etc/ssh`, `/System/Volumes/Data/private/etc/ssh`, `/private/etc/krb5.keytab`, `/etc/krb5.keytab`, `/System/Volumes/Data/private/etc/krb5.keytab`, `/private/etc/master.passwd`, `/etc/master.passwd`, `/System/Volumes/Data/private/etc/master.passwd`, `/Volumes`, `/System/Volumes/Data/Volumes`, `/Network`, `/System/Volumes/Data/Network`, `/home`, `/System/Volumes/Data/home`, `/cores`, `/System/Volumes/Data/cores`, `/Library/Logs`, `/System/Volumes/Data/Library/Logs`, `/private/var/log`, `/var/log`, `/System/Volumes/Data/private/var/log`, `/private/var/db/diagnostics`, `/var/db/diagnostics`, `/System/Volumes/Data/private/var/db/diagnostics`, `/private/var/db/uuidtext`, `/var/db/uuidtext`, `/System/Volumes/Data/private/var/db/uuidtext`, `/opt/homebrew/etc`, `/opt/homebrew/var`, `/System/Volumes/Data/opt/homebrew/etc`, `/System/Volumes/Data/opt/homebrew/var`, `/usr/local/etc`, `/usr/local/var`, `/System/Volumes/Data/usr/local/etc`, and `/System/Volumes/Data/usr/local/var`. Treat every listed value as a subtree, including a file entry itself. Also exclude declared actual/configured homes/auth roots and operator checkout/known evidence roots. These are policy declarations; never test them by opening real credential/secret files. Arbitrary custom mounts/unknown secrets/other spellings are not comprehensively excluded; no exhaustive claim.
5. Deny **file-read-data**, including directory-content reads, within each private-temporary prefix `/private/tmp`, `/tmp`, `/System/Volumes/Data/private/tmp`, `/private/var/tmp`, `/var/tmp`, `/System/Volumes/Data/private/var/tmp`, `/private/var/folders`, `/var/folders`, `/System/Volumes/Data/private/var/folders`, except TRUST/WORK and their complete declared alias sets. Metadata/readlink stays allowed by default on temp paths and their ancestors; sensitive-root metadata stays denied by rule4. This makes the metadata limitation explicit. Generate one filtered denial: temporary-prefix membership AND NOT any TRUST alias AND NOT any WORK alias, using require-all/require-not. No broad temporary-directory allow, no dependence on “last rule wins.” Do not import old or other-role scratch. This temp-data restriction, especially `/private/var/folders`, was **not present in the successful broad diagnostic** and remains untested; startup is not promised.
6. TRUST/WORK must be fresh, private, non-symlink, disjoint descendants of one nonce root under `/private/tmp`, outside unconditional exclusions; SOURCE is TRUST/source, STAGE is WORK/stage. Derive paired aliases for each from the same relative components under `/private/tmp`, `/tmp` and `/System/Volumes/Data/private/tmp`; emit every alias in the appropriate exception/protection. Test available spellings against the same synthetic inode before counting an alias probe; absent/non-equivalent spellings are recorded as untested, never passing. Validate containment by path components, not string prefixes (`WORK-other` is outside WORK). Reject root-wide exceptions, overlaps or aliases outside their declared prefix. No universal mount/case/firmlink/hard-link claim. Tool paths resolving within an excluded root fail guard_unavailable; the original home-tool exception is removed, not broadened.
7. Model CLIs keep normal login outside the payload guard, with repository-code execution tools disabled. The trusted driver uses fixed argv, close_fds, minimal sanitized child environment and synthetic HOME/CFFIXED_USER_HOME/TMPDIR. It never imports package/test/app modules. No credential environment, configuration copies or auth operations enter payload scratch. Unknown host secrets outside excluded paths and Keychain/Mach/broker access are outside the guard's proven boundary; actual provider queries remain prohibited by reviewed code/briefs. A direct AF_UNIX denial never proves broker isolation.

The read change is intentional: a random file outside WORK in an unexcluded system location may be readable. Do not describe `directReadOpenDenied` as “all external reads denied.” Direct network denial is retained; child writes are narrowed/restructured and parent canary side effects are newly authorized as enumerated. Qualified probes measure only their operations; declared rules/cooperative restrictions are not hostile-code containment. Other-role roots under home receive full file-read* denial; those under private temp receive data denial only, with metadata/xattr limitations. Do not describe those placements as equivalent or generalize canary alias results to unprobed system-secret roots.

### Generation, configuration and template acceptance

Use actual account home from the OS account record, the trusted parent's nonempty absolute HOME, and model-CLI launch homes/config roots declared by the development driver; never substitute the child's synthetic HOME. Secret-pattern scan all parameter strings before persisting/dispatching a profile; matches fail sensitive_content without echoing them. This is pattern rejection, not proof all secrets were found. Profile path literals accept ordinary spaces and NFC Unicode, but reject NUL/control characters, quote, backslash, nonabsolute paths or components `.`/`..` before emission. Bound to the existing1024-byte path limit. Use a single audited encoder that wraps these validated strings as quoted SBPL literals; never interpolate unrestricted user/evidence strings or evaluate shell. Every mandatory fixed/configured exclusion and every declared alias must appear in deterministic generated bytes. Static/golden acceptance covers omitted exclusion, space-containing path, quote/backslash/control/non-NFC rejection, root/descendant/prefix-sibling containment, known auth/tool overlap and unresolved config. Static presence is policy evidence, not measured access to real secrets. ### Lifecycle and cleanup

Trusted parent exports only audited tracked SOURCE bytes into TRUST/source; no probe-only SOURCE contents.
