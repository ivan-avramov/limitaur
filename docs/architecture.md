# Architecture

`LimitaurCore` contains public Foundation value models, provider decoders, source-specific credential loading, URLSession transport and an actor scheduler. The AppKit executable owns the status item, popover, settings and diagnostics. No runtime package dependencies are used.

Credential files are opened by descriptor with `O_NOFOLLOW`, nonblocking and a 1 MiB bound. Background Keychain discovery uses a noninteractive `LAContext` and serialized classic Keychain interaction policy. It checks restoration, attempts a noninteractive reset if restoration fails, and reports denial. Every background query sets the classic policy to false before reading or returns denied. Only the explicit Connect / Authorize action may request OS-mediated read access to the existing item. Independent profile loads run off the monitor actor with at most eight concurrent synchronous OS reads and generation checks. Sleep cancels queued loads and invalidates their results; wake revalidates those sources. A synchronous Security or file operation already running cannot be forcibly stopped safely, so the eight-slot bound remains until those calls return. Credentials remain in session memory and are never included in snapshot models. Requests use fixed HTTPS URLs, an ephemeral session, no cookies or cache, rejected redirects and a streaming response bound. Errors shown to users are fixed descriptions.

The monitor groups subscriptions by provider, token fingerprint and selected account context. A shared entity owns single-flight requests, cache and throttle deadline. Profile bindings own generation and authentication pause. Completions require matching entity epoch and binding generation. Detached state is removed after throttle expiry; admission is bounded at 256 entities while unexpired throttles remain authoritative. Freshness and backoff use continuous monotonic time; reset dates use wall time. The status view receives only normalized snapshots and health.

The status bar drawing view forwards hit testing to its parent status button and is decorative for accessibility; actual click, anchor, keyboard, theme and accessibility behavior still requires an interactive app check. UI refresh uses 30 to 31.5 second timer intervals with tolerance, while the scheduler keeps its 30-second minimum. Aggregate statistics include only provider outcome counts, default-profile eligibility counters and aggregate validity deadlines; they contain no account, path or fingerprint values. A known credential expiry joins freshness and reset deadlines in the coalesced display timer, so an expired binding can invalidate statistics before the next network poll.

Settings separates the Indicators menu (1–8, default 3) from Accounts. Indicator changes persist only the presentation integer, resize immediately, and issue a coalesced local display query without account reconfiguration, credential reads or HTTP work. Accounts retains its own Save/Cancel flow. Demo uses an in-memory indicator preference, synthetic monitor dependencies and guarded action routing; account/connect actions are disabled and refresh is inert. No account discovery beyond configured sources occurs.

The monitor publishes at most eight ordered candidates with snapshot identity, freshness proof and an increasing display revision; the compatibility selected array remains the first three. Presentation projects all profile states and selected bars from one wall/continuous-clock sample. Snapshot-scoped observed reset and balance/reset-credit expiry states remain sticky through backwards wall-clock changes until replacement data arrives. Delayed stream/query results cannot restore an older revision, and local expiry observations are handed back without fetching. The existing one-shot scheduler includes freshness, quota resets and credit expiry, and coalesces deadlines crossed while arming. Tests use injected clocks and action/credential/transport spies. Actual redraw, accessibility and interaction behavior remain independent review and release qualification concerns.

Offline URLProtocol and direct policy/delegate tests exercise request construction, a synthetic 302 response, the redirect decision, streaming bounds, watchdog and cancellation wiring. They do not establish real TLS or proxy behavior, an actual 3xx over the wire, URLSession's own resource-timeout implementation, cookie/cache interoperability, or internal platform retries. Those behaviors require separate platform integration evidence.

Default demo presentation uses a frozen synthetic clock for its inspection lifetime; explicitly injected test clocks and live clocks retain their normal behavior. Pending display delivery buffers only the newest value for each consumer, while outcome and eligibility counters remain actor-owned. At cache expiry, existing authentication/failure/throttle status is retained with stale context; only previously healthy or partial status becomes stale. Tooltip and accessibility summaries name affected provider/account labels.
