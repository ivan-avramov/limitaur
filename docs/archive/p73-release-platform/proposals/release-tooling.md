## Goal and authority

Create a single app-version source and local prepare/verify tooling that cannot report release readiness without evidence for an unchanged frozen artifact. This increment does not collect live evidence, release, publish, install or change provider behavior.

Settled by operator: native Swift/AppKit, macOS 26+, no runtime package dependencies; preserve existing tests; P119 complete; no push; normal Claude CLI login without credential copies; actual UI, current built-bundle provider access, sustained performance and default-backend qualification remain release gates. API/hybrid and Cursor are out of scope.

Designer choices proposed for Go: VERSION starts at 0.1.0; local SwiftPM build-tool generation embeds the full version; strict evidence schema v1; prepare requires a clean committed source; verify executes no candidate/build/test code; ad-hoc signing only. The tool is an operator-controlled local gate, not a cryptographic attestation service. Hashes establish consistency, not truth of operator-supplied observations.

## Version contract

VERSION is the sole authored app version. Read bounded UTF-8/ASCII bytes, maximum 4096 bytes. Accept SemVer 2.0.0 with zero or one terminal LF; reject other whitespace, CR, BOM, extra lines, Unicode digits, core/numeric-prerelease leading zeros, empty identifiers and invalid characters. Build identifiers may contain leading zeros. Keep numeric components as strings for validation; no integer overflow or truncation. Initial bytes: `0.1.0\n`.

CHANGELOG.md contains exactly one `## [Unreleased]`. Initial authored content has no dated release entry. Ordinary builds need no dated entry; development prepare/verify permit its absence. Non-development prepare/verify require exactly one `## [<full VERSION>] - YYYY-MM-DD` heading with a valid Gregorian date no later than the phase's UTC date. Other historical version headings are permitted but duplicates of any version heading fail. A dated entry is a proposed release note, not evidence of publication. Never add or date it automatically. Document compatibility surfaces (adapter interfaces, persisted configuration, documented diagnostics). Before 1.0, breaking/feature changes bump minor; fixes patch.

A local SwiftPM build-tool plugin reads root VERSION as a declared input and generates a Swift constant into its plugin work directory. Its generator validates the grammar and uses safe Swift string literals. No network, credential access, Git command, source mutation, checked-in generated version, or runtime package dependency. A VERSION edit must regenerate on the next ordinary `swift build`; direct SwiftPM build/test must work without a preliminary script. Full metadata is compiled into the executable, not loaded from a mutable working-directory VERSION or an absolute build path at runtime.

`Limitaur --version` with exactly two arguments prints the full SemVer and LF to stdout, exits 0 before creating NSApplication, settings, credentials, monitor or transport. Extra arguments fail with existing fixed diagnostics. The same compiled value supplies an `About Limitaur…` item appended to Settings after existing items, preserving their indices, and an AppKit About dialog containing full SemVer. Set AboutPanelOptionKey.applicationVersion to the compiled full SemVer, and version to the bundle build number when available (omit that key for unbundled tests); do not use AppKit's implicit short-version display. About performs no auth/refresh/preferences writes in real or demo mode. New tests inspect the production About options/menu, not an interactive dialog. Existing source assertions were inventoried: no exact parent Settings count/last-item or help-output assertions; submenu count8 and parent indices0/2 must stay unchanged. Help lists --version. Both Swift and Python parsers consume the same committed version-vectors.json in new tests.

The build script retains its positional output + SwiftPM options interface; `--build-number VALUE` is a new script option, accepted after output and removed before SwiftPM dispatch, duplicate/missing values rejected. Version script helpers use Python standard library only (Python 3.11+ is a documented development prerequisite). Start Python with `-I -S -B`; load release_support by fixed sibling absolute path using importlib, without adding source/current-directory paths to sys.path. The shell wrapper resolves its root safely and invokes the selected interpreter with these flags. Bundle plist template contains no separately authored version literals. Populate CFBundleShortVersionString with numeric core, LimitaurSemVer with full SemVer, LimitaurSourceRevision with full HEAD object ID, CFBundleVersion with the validated build number. About/--version use compiled full SemVer; prepare compares actual CLI output and plist to VERSION. Build number/revision need not be compiled into the executable. No extra numeric-core packaging restriction beyond VERSION's 4096-byte bound and decimal syntax. Reject no valid core on the basis of CFBundleVersion's separate digit limits.

Build number policy: explicit canonical decimal integer 1..9999, or full-history `git rev-list --count HEAD` in that range, normalized to `<N>.0.0`. Reject zero, signs, padding, whitespace, out-of-range, shallow history without explicit number, and unavailable HEAD. Never silently wrap/reset. This conservative Apple-compatible subset is separate from the SemVer core, whose three decimal components have no artificial build-number limits. Record explicit versus Git-count origin. Ordinary local build can use a dirty tree but cannot qualify release; source revision then denotes HEAD, not a claim of clean sources. Fail closed on inability to obtain revision. No tags are created.

Bundle output must be new, with no symlink component; never merge into or delete a pre-existing output. Copy executable/plist and any necessary local resources, set LSUIElement=true and LSMinimumSystemVersion=26.0, lint and verify executable/signature using fixed system tools, and ad-hoc sign locally. Preserve ordinary argument paths with spaces. Do not use shell evaluation/interpolation for metadata or evidence.

## CLI and phase separation

`/absolute/path/to/python3 -I -S -B scripts/release-check.py prepare --output ABSENT_ABSOLUTE_DIRECTORY [--build-number N] [--backend default|native] [--proposed-tag vSEMVER] [--development]`

`/absolute/path/to/python3 -I -S -B scripts/release-check.py verify --candidate ABSOLUTE_DIRECTORY --evidence ABSOLUTE_DIRECTORY [--proposed-tag vSEMVER] [--development]`

Resolve repository root from the script, never from evidence. Require the prescribed isolated Python flags at entry before loading local helpers; otherwise fixed startup error (ambient startup before entry is outside a misinvoked command's guarantee). No user-supplied executable, test command, custom manifest path, custom URL, shell fragment, evidence-defined action, bypass flag or arbitrary SwiftPM arguments. Backend defaults to default; native is available for truthful development diagnostics. Release readiness requires default-backend evidence for this exact frozen artifact. Prepare never reports releaseReady=true because live evidence is a later phase. JSON stdout fields are exactly schemaVersion=1, phase (`prepare`/`verify`), prepared (bool), releaseReady (bool), development (bool), reasons (sorted unique code array), freezeId, manifestSHA256, artifactTreeSHA256, executableSHA256. Last four are null until known. Never echo rejected strings/content or raw subprocess output. Development always forces releaseReady=false. Reports go to stdout only, not into candidate/source/evidence.

Decision table: successful prepare exits0, prepared=true, releaseReady=false, reasons=[] (development adds development_mode); failed prepare exits1, prepared=false. A missing dated release heading is permitted only for development prepare; normal prepare fails with missing_release_heading. proposedTag remains optional in both modes. Valid verify with all gates passing and development=false exits0, prepared=true, releaseReady=true, reasons=[]. Structurally valid missing documents/failed or unverified observations/native backend/missing release heading are qualification failures: exit1 normally, exit0 with --development, prepared=true, releaseReady=false, applicable fixed reasons. Development verify always adds development_mode even if all gates pass. Normal verify of development-prepared inputs blocks with development_mode (exit1). An omitted/mismatched tag option relative to recorded proposedTag is input_mismatch (always exit1); matching null is valid; no tag is required. Missing required fields, wrong types, bad dates/identity/hashes, unsafe inputs or source/artifact/input mismatch always exit1 including development; report prepared=false on such structural/identity failures. CLI misuse exits2 with fixed usage text and no raw argv. Internal errors exit1 with internal_error. A development-prepared artifact must be re-prepared without --development before release qualification.

Fixed reason-code vocabulary: invalid_version, invalid_changelog, invalid_build_number, invalid_tag, source_dirty, source_changed, source_unsupported, output_exists, unsafe_path, unsafe_input, sensitive_content, invalid_manifest, invalid_evidence, identity_mismatch, input_mismatch, artifact_mismatch, signature_failed, dependency_failed, deployment_failed, guard_unavailable, guard_probe_failed, build_failed, tests_failed, version_mismatch, missing_evidence, gates_failed, missing_release_heading, native_backend, development_mode, internal_error. Use the most specific code(s); schema errors use invalid_manifest/invalid_evidence, no exception text.

The public command does not rely on the caller already being sandboxed. It never imports app/package/test code in that parent. Keychain/preferences IPC is not established as denied; real home denial does not claim broker isolation. Probe direct sentinel read-open/write-open denials, TCP connect denial, AF_UNIX connect denial and allowed scratch write for each recipe; fail closed on unavailable/failed guard. Diagnostic profiles also require protected executable write-open denial. These syscall probes are not broker/IPC containment attestations. Controls must succeed unguarded against the same synthetic resources first: readable/writable nonsecret sentinel outside allowed scratch, and controlled local127.0.0.1 ephemeral TCP and AF_UNIX listeners. The AF_UNIX socket path is accessible for metadata lookup to the child, so the measured connect denial is not merely a missing/inaccessible socket pathname. Guarded failures must be EACCES/EPERM within2seconds, not ENOENT/ECONNREFUSED/timeout; scratch write succeeds. The parent listener/control/probe is trusted supervisor infrastructure only; no network listener is opened by a guarded test suite. Policy is deny network* including AF_UNIX, with no build-service socket exception. If swiftbuild needs a denied socket, record failure; do not broaden the profile or claim native as default. A no-op profile must fail these probes. Close both listeners and remove sentinels after probing. For diagnostic protection controls, open the actual staged executable O_WRONLY without O_TRUNC and close without writing; the unguarded control must succeed and the guarded open must be denied. Do not mutate executable bytes for this probe. Record separate build and diagnostics profile SHA256 values and probe records as defined below, not one hash standing for two policies. Every guarded launch is bound to its recorded recipe/hash. No OS Keychain/IPC containment claim: real credential access is prohibited by reviewed code/phase instructions, injected Keychain tests use fakes, and the guard is not a defense against hostile helpers. Run fixed release build/bundle and all suites listed below under this guard. The trusted release-tooling parent is a separate isolated-Python process, never the authenticated model CLI process. App/package/test payloads run only in measured child profiles. New parent-tooling code is not executed unguarded before its frozen-code approval. Synthetic prepare tests use a Python-only internal runner seam, never recursive real prepare. Capture stdout+stderr in memory with a32MiB combined cap per process; on overflow terminate its process group and fail with the phase code. Discard raw output after extracting sanitized pass/error records; never write/forward raw subprocess logs. Cleanup private export/scratch on success/failure; retain only published candidate and sanitized stdout report.

Check plist properties, required regular executable and mode, compiled --version (under the guard), signature integrity, and every executable Mach-O slice: macOS minimum exactly26.0, architecture equals selected host architecture, load dependencies only canonical absolute /usr/lib/ or /System/Library/ paths without dot/dotdot; reject relative/@rpath/@loader_path/@executable_path dependencies and other non-system dependencies. ## Evidence schema v1

Selected evidence directory contains exactly review.json, integration.json, ui.json, performance.json and backend.json. Missing documents mean blocked; extra/unknown fields or documents fail validation. Each is an object with schemaVersion=1; six identity fields named above; observedAt (UTC RFC3339 whole seconds, actual date); and `result`, specific below. No free-form text, arbitrary URLs, paths, environment or raw account identifiers. Each result object has only the specified fields.

Normative nesting: all six identity fields and observedAt are direct root fields; every field in the following result lists is a direct child of result unless explicitly nested with `{}`. Status enums allow passed/failed/unverified, verdict allows accepted/rejected/unverified, backend name allows default/native; all specified booleans allow both true and false structurally. Values below are qualification requirements, not schema-only enums. An otherwise valid negative/unverified result gives gates_failed; missing whole files gives missing_evidence; missing fields/wrong types/extra keys give invalid_evidence. Performance providers is a two-string array whose wrong order/identity is invalid_evidence. nominalRefreshSeconds is a positive integer, and values other than30 give gates_failed. credentialPath enum violations are invalid_evidence, supported test/unverified values give gates_failed. Placeholder tool/input digests are syntactically allowed by validate_manifest; actual semantics mean recomputing tree/executable internal consistency there and real tool/source comparison only in orchestration, so zero placeholders cannot pass full verification. ui/performance indicatorCount disagreement returns gates_failed, not a schema exception. Identity-field disagreement raises ReleaseError(identity_mismatch). No nullable observations; unverified is represented by status/verdict or false. Performance fields remain required even on a nonqualifying run, as in the collector.

preparedAt/observedAt syntax is exactly YYYY-MM-DDTHH:MM:SSZ, valid Gregorian UTC, no leap seconds. Require preparedAt<=observedAt<=verification UTC time plus1second. Performance result additionally has measurementStartedAt with that syntax, >=preparedAt; observedAt means completion of the full warmup+measurement and must be >=measurementStartedAt+warmupSeconds+measuredSeconds-1second. The one-second tolerance accounts for whole-second recording, not a general clock-skew exemption. A backwards clock that violates chronology blocks; timestamps do not authenticate observations.

- review: verdict=`accepted`, unresolvedRequiredFixes=0, independent=true, panelAccepted=true. These are explicit local operator attestations, not model-authenticated signatures.
- integration: result has exactly productionBundle/codex/claude; productionBundle=true; each provider-nested credentialPath enum is production/test/unverified (only production qualifies); codex/claude each `{status:"passed",defaultProfile:true,credentialPath:"production"}`. No keys/account responses or profile labels. This states actual built-bundle production adapters worked; normal Claude CLI login does not qualify app access.
- ui: indicatorCount integer 1..8; actualAnchoredApp=true; light/dark/increasedContrast/anchoring/click/keyboard/scroll/accessibility each `passed`. These are operator observations on the exact bundle. Static renders do not pass these gates.
- backend: name=`default` for release readiness, releaseBuildPassed=true, testedArtifact=true. validate_evidence checks name agreement with manifest and those result flags; verify owns native_backend and the default-only release policy. Must also agree with manifest backend/build checks. Native-only preparation cannot gain default qualification by a self-reported boolean.
- performance: measurementStartedAt as above; requestedSeconds integer>=1 recording the collector --seconds argument; indicatorCount integer 1..8 matching ui; dropdownClosed=true; nominalRefreshSeconds=30; providers=["codex","claude"]; collector field names flat beside these workload fields inside result. Require `classification="qualifying workload"` (other permitted string: `smoke or nonqualifying workload`), warmupSeconds>=60, measuredSeconds>=600, sampleIntervalSeconds=2, maxRSSMiB<50, meanRSSMiB<=maxRSSMiB, medianRSSMiB<=maxRSSMiB, cpuSeconds>=0, cpuPercentOneCore<0.1 and equals 100*cpuSeconds/measuredSeconds within absolute tolerance 1e-9, rssTargetMet=true, cpuTargetMet=true, descendantCountObserved=0, unaccountedExitedChild=false, defaultProfileStateEligible=true, qualifying=true; refreshOutcomes permits an object with any subset of codex/claude keys; each value permits any subset of success/partial/failed/unauthenticated/throttled/unavailable integer counts, no unknown keys. Qualification requires explicitly present success>=18 for both providers and every other present outcome=0; missing successes never confer eligibility. Empty/failed-only unchanged collector reports are structurally valid nonqualifying observations. samplingLimit is exactly `RSS peaks and children born and exited between samples may be missed`. All numeric values finite/nonnegative, booleans forbidden as numbers; measuredSeconds must be positive, warmupSeconds integer, sampleIntervalSeconds integer, remaining resource numbers finite real-or-integer. Validate medians/means >=0 and <=max; recompute targets, never trust labels alone. Misstated derived labels/CPU percent are invalid_evidence; valid unfavorable metrics are gates_failed. warmupSeconds and sampleIntervalSeconds are integers in the actual collector; cpuPercentOneCore is the unrounded calculation, so1e-9 is an explicit comparison tolerance. The workload and observations remain subject to documented sampling limits. Wrap unchanged collector output with binding/workload fields; no collector edits or missing-value eligibility inference.

Evidence files are local structured attestations. The tool cannot prove an operator did not fabricate a passing JSON document. Document this limit prominently; readiness means validated, correctly bound evidence under the local trust model, not notarization or distribution approval. API live readiness is separately unverified and never advertised by this subscription release gate.

Exact performance derivations from unchanged collector: goodFetches means explicit success>=18 for codex and claude and no other positive outcomes; workload = warmupSeconds>=60 AND requestedSeconds>=600 AND defaultProfileStateEligible AND descendantCountObserved==0 AND NOT unaccountedExitedChild AND goodFetches. qualifying must equal workload; classification must equal `qualifying workload` iff workload, otherwise `smoke or nonqualifying workload`. Resource targets are separate: rssTargetMet=(maxRSSMiB<50), cpuTargetMet=(cpuPercentOneCore<0.1). Do not conflate qualifying workload with meeting targets. measuredSeconds is actual elapsed and must be>=requestedSeconds; CPU comparison above uses actual elapsed. No collector rounding is introduced.

Negative decision vectors (otherwise consistent fields): maxRSS=50, qualifying=true/classification=qualifying workload, rssTargetMet=false => gates_failed; CPUpercent=0.1/correct cpuSeconds, cpuTargetMet=false => gates_failed; requestedSeconds599/measuredSeconds600 with qualifying=false/nonqualifying classification => gates_failed; warmup59 => workloadfalse/gates_failed; missing success keys, failed-only or empty outcomes => workloadfalse/gates_failed; helpers>0, unaccounted children or ineligible default profiles => workloadfalse/gates_failed. Any corresponding stale qualifying/classification/target label or wrong CPU equation => invalid_evidence instead. measuredSeconds<requestedSeconds is invalid_evidence. The default-profile boolean is an operator/collector attestation whose underlying proof is not reconstructed from this wrapper.

## Parsing and file boundary

Evidence/manifest: at most 1 MiB/file, 8 MiB total, 4096 entries, JSON depth<=16; strings<=4096 characters, except proposedTag<=4097 (VERSION may use all4096 ASCII bytes without LF). Reject duplicate JSON keys, nonfinite constants, exponent/range overflow, invalid UTF-8/BOM, wrong types, unknown fields and noncanonical identifiers. Integers are 0..2^63-1 unless a tighter field bound applies (bool rejected); finite nonnegative IEEE754 reals only where specified. Permission modes integer0..0777. Hashes/UUID/object IDs checked structurally and semantically; UUID canonical lowercase v4/standard variant; source IDs lowercase40 or64hex matching repository format. Manifest artifact sizes bounded to 256 MiB/file and 512 MiB total; streaming hashes, bounded traversal. File paths/entry names <=1024 UTF-8 bytes. No abbreviated object IDs. Manifest bytes must equal canonical_json(parsed_manifest). validate_manifest recomputes the tree digest from entries/root mode and checks executableSHA256 against the unique Contents/MacOS/Limitaur file entry; it requires Contents/Info.plist and Contents/_CodeSignature/CodeResources file entries, plus their parent directories. It validates structure only, not those files on disk.

Open candidate/evidence directories with no-follow descriptor traversal from trusted user-selected absolute roots; disallow symlink components in the absolute input itself. Open members relative to held directory descriptors with O_NOFOLLOW|O_NONBLOCK, fstat same descriptor, require regular files (link count=1) or expected directories; bound reads on that descriptor. Reject symlinks/FIFO/sockets/devices/traversal including intermediate links before data reads. Check immutable metadata after reads/hash walks. Hash only selected artifact files and necessary known source inputs, never follow arbitrary manifest paths. Check supplied entry map against actual walk, not vice versa. No paths read from evidence. Do not read real credentials or scan home directories.

Scan UTF-8 review briefs/staged review documents before model dispatch, and raw UTF-8 manifest/evidence bytes before parsing. Patterns (Python re syntax, ASCII): `-----BEGIN [A-Z ]*PRIVATE KEY-----`; `(?i)authorization\s*[:=]\s*[\"']?bearer\s+[A-Za-z0-9._-]{10,}`; `\bsk-(?:ant-)?[A-Za-z0-9_-]{16,}`; `(?i)\"(?:access_token|refresh_token|api_key)\"\s*:\s*\"[^\"\s]{8,}\"`; `\beyJ[A-Za-z0-9_-]{8,}\.[A-Za-z0-9_-]{8,}\.[A-Za-z0-9_-]{8,}\b`. Report sensitive_content only, never a match. Ordinary version0.1.0/build42.0.0 and hex digests must not match. This is pattern rejection, not proof of absence of all secrets. Structured schema rejects unneeded text. Subprocess diagnostics use fixed reason codes and sanitized aggregates; no raw failure logs in reports.
