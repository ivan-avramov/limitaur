# Limitaur

Native macOS 26+ menu-bar monitor for existing Codex and Claude local sessions. It reads subscription usage and displays the highest fresh quota percentages as narrow bars that fill upward. Beside each bar, two codes are stacked: the provider code on top (`CL` Claude, `CX` Codex; full table in `docs/provider-codes.md`) and the window code below: `5` session or up to six hours, `W` weekly, `M` monthly, `$` spend, `?` unknown, followed by a model initial for model-scoped limits, so Fable's weekly limit reads `WF`. An empty slot shows a dash, and names a configured provider that is currently unavailable, stale or signed out, in dimmed letters. The Indicators menu selects 1–8 bars (default 3) immediately; Accounts… remains a separate dialog. Yellow starts above 80%; red above 95%.

Two experimental layouts, a labelled jar and a logo-shaped gauge, remain in the source behind `RingView.layout` for comparison and are not used by default. A monochrome black-on-transparent square PNG at `Resources/providers/<providerID>.png` is picked up by those layouts; that directory is ignored by git, so logos never enter the repository. The app does not predict usage, buy credits, redeem resets, refresh credentials, or send telemetry.

## Authentication and sources

Codex defaults to `~/.codex/auth.json` and requires `tokens.access_token` plus `tokens.account_id`. An API key alone cannot supply subscription limits. Claude defaults to reading the `Claude Code-credentials` Keychain item through `/usr/bin/security find-generic-password -a <user> -s "Claude Code-credentials" -w`, the way Claude Code writes it, bounded to five seconds, falling back to `~/.claude/.credentials.json` only when the item is absent. A configured Claude file path bypasses Keychain. Settings contain labels and absolute source paths, never tokens. Existing sessions are required; Limitaur does not register its own OAuth client. A background Keychain denial shows its wording on the account's row only for a paused account or a suspended read. While an enabled account has no usable credential (expired, rejected, or not yet readable), Limitaur re-reads that account's configured source without interaction every five minutes, and a manual refresh does so at once; it resumes by itself when the provider app has written a different unexpired token. A background read that does not return within five seconds, or that a person answers with Deny or Cancel, is abandoned and that source is not read again in the background until a Connect / Authorize read completes with the item found or absent, or the app relaunches, so at most one Keychain dialog per source per launch can appear without user action; it is drawn by the system and may stay on screen until answered. A re-check never refreshes or writes a token, never bypasses a provider throttle, and a token the provider rejected (HTTP 401/403) is not retried until it changes. Accepted sensitive areas: a configured credential file under a privacy-protected folder can raise a system privacy dialog on first access, which a re-check never is for a configured path because a launch, Settings or Connect load precedes it (the fallback `~/.claude/.credentials.json` is a fixed home-directory path outside protected folders, read only when the Keychain item is absent); a credential file on a network, removable or iCloud volume can hang a read and hold one of eight lookup slots; and the whole credential item, refresh token included, passes through a child `/usr/bin/security` process, a pipe and process memory once per interval per paused source, and is re-read after a 401, 403 or 429 on a bound source (only the access token, expiry and account are kept). Use the account's **Connect / Authorize** action to request macOS access to that existing item; Refresh does not clear a rejected credential. A Keychain dialog naming `security` that appears while Limitaur runs comes from Limitaur; answer it Allow or Deny, never Always Allow, because Always Allow would grant `/usr/bin/security`, and so every process of the user, standing access to the item. When `/usr/bin/security` is already on the item's access list, as it is for an item Claude Code wrote, Limitaur adds no exposure beyond Claude Code's own. No in-process Keychain API is used for Claude. Probe record (scripts/keychain-acl-probe.sh, 2026-10-24, build 45 on macOS 26): the helper read passed on an item written by `security`, across a `-U` rewrite, with two-line JSON and with a non-ASCII byte; the missing-item case exposed an exit-code normalisation defect fixed in 45b66e1; the deliberately untrusted item timed out after five seconds as designed, and its Keychain dialog stayed on screen after the read was abandoned until the operator answered it (Allow, one-time), so a dialog is never closed by Limitaur: the per-launch suspension is the bound on how many can appear. Live record (0.2.0, 2026-10-25, this machine): after Claude Code renewed the session, the next poll's 401 led to a re-read that bound the new token within the same 15-second sample, and after a night's sleep the wake re-check bound the token Claude Code had renewed meanwhile and usage was back within six seconds of wake; no Keychain dialog, no suspension. The expiry nudge has not yet run live, because a `claude` session renewed the token first both times.

Expiry nudge (Settings → "Run claude when the Claude session has expired"; on by default, turn it off in Settings; stored as `claudeNudgeEnabled`, an absent key means on). When a re-check of the default Claude Keychain session (not a configured file path, and not the fallback file) shows that the stored token has expired, Limitaur runs `claude -p hi --model haiku --safe-mode --no-session-persistence --strict-mcp-config --tools ""` so that Claude Code renews the session itself; Limitaur still never refreshes or writes a token. It runs only after such a re-check (never preventively, never on a Keychain denial or a wake re-check), at most once per hour (the last attempt is kept in `nudge.lastAttempts` across relaunches), and one at a time. The executable is the first of `~/.local/bin/claude`, `/opt/homebrew/bin/claude`, `/usr/local/bin/claude`, `~/.claude/local/claude` that is executable, a regular file owned by you or root without group or other write permission, in a directory owned by you or root without other write permission; the symlink is resolved first, the resolved file and both directories (the candidate's and the resolved file's) are checked, and a candidate whose directory path contains `:` is skipped. A directory that is group-writable by the `admin` group (the default Homebrew prefix, `/opt/homebrew/bin`) is accepted, because members of `admin` can become root anyway; a directory writable by any other group or by others is rejected, and so is a file writable by its group, and the row then says "claude command not found". The program started is the checked resolved file; for a script launcher (the `~/.claude/local/claude` wrapper, an npm launcher) its interpreter and the files it runs are not checked. Two Limitaur processes never run `claude` at once: the run holds an exclusive lock on `~/Library/Application Support/Limitaur/nudge/lock`, and a run that finds it held ends as a failed launch. The child gets exactly the environment `HOME`, `USER`, `LOGNAME`, `PATH` (the system directories first, then the candidate's directory and the resolved file's directory), `LANG=en_US.UTF-8`, `TMPDIR=~/Library/Application Support/Limitaur/nudge/tmp/` (created, with its parents, at mode 0700), `DISABLE_AUTOUPDATER=1` and `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` (so an attempt sends no telemetry or error reports); its working directory is `~/Library/Application Support/Limitaur/nudge`; its output is discarded and Limitaur's runner stops it after a 60 second timeout plus a 10 second termination grace. Boundary, verified on claude CLI 2.1.310: `--safe-mode` disables CLAUDE.md and memory files with their imports, skills, plugins, hooks, MCP servers, custom commands and output styles while authentication works; `--no-session-persistence` leaves no transcript and no project entry in `~/.claude.json`; `--tools ""` removes tools. Not excluded: managed (enterprise) policy; unverified under `--safe-mode`: whether Claude Code applies the settings `env` block and the settings-defined commands `apiKeyHelper`, `awsAuthRefresh`, `awsCredentialExport` and `otelHeadersHelper`; an applied `apiKeyHelper` would authenticate with an API key and never refresh the OAuth token, so every attempt would succeed and spend one billed request per hour without renewing the session, therefore turn the setting off (Settings → "Run claude when the Claude session has expired") on a machine whose Claude Code settings configure any of them or set `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `CLAUDE_CODE_USE_BEDROCK` or `CLAUDE_CODE_USE_VERTEX` in an `env` block, because such a machine's Keychain session is never renewed and every hourly attempt would spend a billed request; the child's environment carries no proxy variables, so proxies are unsupported for the nudge. Each attempt spends one small Haiku request. On quit, Limitaur waits up to five seconds for a running nudge; a slower one is left to finish on its own: the 60-second limit is enforced by Limitaur's runner and ends with the app, so a child that survives quit is not bounded by Limitaur, and it is not killed by Limitaur. The row says "Running claude to renew the session" while it runs, and "claude exited without renewing the session; run claude to sign in" or "claude command not found; run claude to sign in" when it fails.

Both providers are polled through observed internal HTTPS usage endpoints. These are not guaranteed public APIs and may change. No browser cookies, transcripts, shell provider commands, or arbitrary account files are used, except that the optional expiry nudge below starts the user's own `claude` as a child process. The two default profiles can be enabled or disabled in Settings. The same panel adds and removes explicitly sourced profiles.

## States and refresh

Unknown means no verified value; zero is a known numeric zero. Unlimited is independent of a numeric balance. Unavailable and authentication failure are account states. Last known data remains visible after a failure and becomes stale after 90 monotonic seconds; stale meters leave the bars. Reset times are absolute and a meter leaves ranking at its reset instant until another fetch confirms usage. A backwards wall-clock change does not restore expired cached usage. Reported balance and earned-reset quantities remain visible with an expired or cached qualifier. Refresh runs at a learned interval per provider while awake: it starts at 50 seconds, stays within 30 to 120 seconds, rises by 10 seconds (or to the `Retry-After`, rounded up to 10 seconds) on a 429 that is not attributed to a superseded token, falls by 10 seconds only after 24 hours and five consecutive clean polls, is reverted with that level blocked for seven days if a 429 follows within an hour, and is persisted; with that policy active a snapshot stays fresh for `max(90, interval + 20)` seconds. It also refreshes on wake, and when the menu opens if the last success is older than 10 seconds. Failure backoff begins at 30 seconds and reaches 15 minutes. `Retry-After` and manual refresh respect provider throttles. While an account holds a provider-declared `Retry-After`, its last usage stays in the bars until the next permitted cycle dispatch plus 13.5 seconds, capped at 300 seconds after the fetch; the menu names the throttle and the true fetch age. A failed provider does not stop another provider.

## Build and run

```sh
swift build -c release
swift test
sh scripts/build-app.sh
open dist/Limitaur.app
```

The bundle script accepts an optional output path followed by SwiftPM build options and queries SwiftPM for the binary directory. The default SwiftPM build backend works on the host; an earlier linking failure occurred only under a retired sandbox harness.

The build script creates a local signed app bundle. It does not install a login item or publish a release. The bundle has no Dock icon.

An ad-hoc signed bundle gets a new identity on every rebuild, so macOS asks again before the app may read the Claude Keychain item. The script therefore signs with a code-signing identity named `Limitaur Dev` when the login keychain has one, or with whatever `LIMITAUR_SIGN_IDENTITY` names, and falls back to ad-hoc. To create the identity once, either use Keychain Access (Certificate Assistant → Create a Certificate…, name `Limitaur Dev`, Self Signed Root, Code Signing) or from a shell:

```sh
W=$(mktemp -d); openssl req -x509 -newkey rsa:2048 -nodes -days 3650 -keyout $W/key.pem -out $W/cert.pem \
  -subj "/CN=Limitaur Dev" -addext "keyUsage=critical,digitalSignature" -addext "extendedKeyUsage=critical,codeSigning"
openssl pkcs12 -export -legacy -out $W/dev.p12 -inkey $W/key.pem -in $W/cert.pem -name "Limitaur Dev" -passout pass:transit
security import $W/dev.p12 -k ~/Library/Keychains/login.keychain-db -P transit -T /usr/bin/codesign
security add-trusted-cert -p codeSign -k ~/Library/Keychains/login.keychain-db $W/cert.pem; rm -rf $W
```

The first launch of a bundle signed with the identity asks once, and choosing Always Allow keeps it across rebuilds. Nothing here notarizes or publishes.

## Version

The version lives in one place: the `string` constant in `Sources/Limitaur/AppVersion.swift`. `Limitaur --version` prints it and exits before any settings, credential or network code runs; About Limitaur… in the Settings menu shows it. The build script reads that constant, stamps its numeric core into `CFBundleShortVersionString` (Apple allows only three integers there, so a prerelease or build suffix appears in `--version` and About but not in the plist), sets `CFBundleVersion` to the git commit count, records the HEAD revision (with a `-dirty` suffix when any build input under `Sources`, `Resources`, `scripts` or `Package.swift` is modified or untracked) in `LimitaurSourceRevision`, checks that the built binary reports the same version, and writes `Limitaur.app.sha256` next to the bundle. `CHANGELOG.md` holds release notes in Keep a Changelog form. Nothing here notarizes, tags or publishes.

## Local diagnostics

```sh
BIN_DIR="$(swift build -c release --show-bin-path)"
"$BIN_DIR/Limitaur" --version
"$BIN_DIR/Limitaur" --check-percent 95.01
"$BIN_DIR/Limitaur" --inspect-fixture codex Tests/LimitaurCoreTests/Fixtures/codex-direct.json
"$BIN_DIR/Limitaur" --inspect-fixture codex Tests/LimitaurCoreTests/Fixtures/codex-app-server.json
"$BIN_DIR/Limitaur" --inspect-fixture claude Tests/LimitaurCoreTests/Fixtures/claude-modern.json
"$BIN_DIR/Limitaur" --rank-fixture Tests/LimitaurCoreTests/Fixtures/ranking.json --now 1800000000
"$BIN_DIR/Limitaur" --rank-fixture Tests/LimitaurCoreTests/Fixtures/ranking.json --now 1800000000 --count 5
"$BIN_DIR/Limitaur" --render-demo /tmp/limitaur-demo
"$BIN_DIR/Limitaur" --demo
"$BIN_DIR/Limitaur" --demo-open-popover
dist/Limitaur.app/Contents/MacOS/Limitaur --check-live
dist/Limitaur.app/Contents/MacOS/Limitaur --read-keychain-service 'Claude Code-credentials'
```

Fixture diagnostics use synthetic JSON, do not access credentials, and output normalized JSON. The optional ranking `--count` accepts integers 1–8; the default remains 3, and invalid explicit values exit with a fixed error and no snapshot. `--check-live` uses the real app bundle adapters, waits at most 20 seconds overall, and emits only provider status and counts. `--read-keychain-service NAME` (only `Claude Code-credentials` or a name starting `limitaur-probe-`) reads that item once through `/usr/bin/security` without interaction and prints one word (`found <bytes>`, `notFound` or `denied …`), never item data. The demo mode is offline and labelled; it opens the popover for keyboard and accessibility inspection. Demo indicator choices remain in memory, while account and connection actions are disabled. Static PNGs show actual jar rendering at counts 1, 3, 5 and 8 in light and dark appearances; they do not verify menu-bar anchoring, keyboard interaction, or the accessibility tree in a running app.

For a qualifying resource measurement, launch the bundle executable with an explicit sanitized aggregate statistics path, enable both default providers, close the dropdown, then sample its PID:

```sh
dist/Limitaur.app/Contents/MacOS/Limitaur --stats /tmp/limitaur-aggregate.json
python3 scripts/measure-resources.py PID --stats /tmp/limitaur-aggregate.json
python3 scripts/measure-resources.py PID --warmup 5 --seconds 30
```

The default samples aggregate parent and descendant RSS every two seconds after 60 seconds of warmup for 600 seconds and computes CPU from nanosecond process counters. The short command is a smoke sample. Record the selected indicator count and keep it fixed, with the dropdown closed, during a qualifying measurement; results for one count do not qualify other counts. A qualifying performance result needs at least 10 successes for each default provider, no failed or throttled requests, both intended defaults continuously eligible, and no child helpers. The statistics file contains only aggregate outcomes and anonymous eligibility counters. RSS peaks and short-lived children between samples can be missed.

Earlier guarded build, test and short resource results are recorded in [performance evidence](docs/performance.md); they do not verify later source edits. Actual UI behavior, Claude app-bundle access and the sustained two-provider resource workload remain unverified. Automatic resume of a paused account (M1 in docs/proposals/credential-recheck.md) is covered by native tests and was exercised live once, on 2026-10-23 with signed build 41, where it did not occur: Claude Code rewrote the Keychain item at 00:47:06Z, five minutes before the bound token's expiry; Limitaur paused the account at the expiry (00:52:06Z) as designed and re-read the item without interaction at about 00:52Z, 00:57Z and 01:03Z, but no re-read yielded a usable credential, and `--check-live` from the same bundle reported Claude unavailable at 01:03Z although that bundle had loaded the item at launch at 00:41Z. The re-check path cannot raise a dialog by design. At 19:14 local the operator found the row reading "Keychain access unavailable; choose Connect / Authorize" with the last fetch 5213 s old, the denied wording: the rewrite had removed the app's non-interactive access to the item although Always Allow had been granted to that identity earlier the same day. Automatic resume therefore does not work for the Keychain source after a Claude Code token refresh; whether every refresh revokes access, or only this one did, is the open question (docs/handoff.md). File sources are untested live. Cursor support is deferred.
## Local demo appearance checks

Run `Limitaur --demo-light` or `Limitaur --demo-dark` to open a synthetic dropdown in that app-local appearance. The demo includes enough provider and account rows to check scrolling, keyboard focus, and accessibility without reading credentials or making requests. `Limitaur --demo` uses the current system appearance. `Limitaur --help` lists the diagnostic options. These commands prepare manual UI checks; they do not establish that those checks passed.

`Limitaur --stats FILE` requires a fresh absolute output path. It refuses existing files, symlinks, and configured credential paths; subsequent measurements write through the descriptor it created.
